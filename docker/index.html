La question fondamentale

C'EST
QUOI
DOCKER ?

Imagine que tu développes une application sur ton ordinateur. Elle fonctionne parfaitement. Tu l'envoies sur le serveur de production — et là, rien ne marche. "Mais ça marchait chez moi !"

Docker résout ce problème en empaquetant ton application avec tout ce dont elle a besoin — le code, les dépendances, la configuration — dans une boîte hermétique appelée conteneur. Cette boîte s'exécute de façon identique partout.

Sur ton laptop, sur un serveur cloud, chez un collègue — le comportement est toujours le même. Docker garantit que l'environnement est toujours identique.

🧠 Les analogies pour comprendre
📦
Le conteneur = une boîte de livraison

Comme les conteneurs maritimes — standardisés, empilables, transportables partout dans le monde sans avoir à déballer.

📸
L'image = la recette du gâteau

L'image Docker est le modèle (lecture seule). Le conteneur est le gâteau fabriqué à partir de cette recette. Tu peux faire 100 gâteaux identiques depuis une seule recette.

🏗️
Docker = le Docker Hub = le supermarché

Des milliers d'images prêtes à l'emploi : nginx, postgres, node, python... Tu les "télécharges" et tu les lances en une commande.

🎼
Docker Compose = le chef d'orchestre

Quand ton app a besoin de plusieurs services (web + base de données + cache), Compose les fait tous démarrer ensemble et se parler.

Les concepts essentiels

4 NOTIONS
À MAÎTRISER

01
📸
IMAGE
Le modèle immuable. Une image contient le système de base, les dépendances et le code. Elle ne change jamais une fois créée. C'est la "recette" depuis laquelle on crée des conteneurs.
02
📦
CONTENEUR
L'instance en cours d'exécution d'une image. Léger, isolé, éphémère. Tu peux en lancer 10 depuis la même image. S'arrête, redémarre, se supprime en une commande.
03
📋
DOCKERFILE
Le fichier de recette. Une suite d'instructions qui décrit comment construire ton image : depuis quelle base, quels fichiers copier, quelles commandes exécuter, quel port exposer.
04
🎼
COMPOSE
Un fichier YAML qui définit et orchestre plusieurs conteneurs ensemble. Une seule commande (docker compose up) lance toute ta stack : web, base de données, cache, proxy.

Par où commencer

LES 6
COMMANDES
ESSENTIELLES

docker run
Lancer un conteneur depuis une image. La commande de base — celle qu'on tape des centaines de fois.
docker run -d -p 80:80 nginx
docker ps
Lister les conteneurs en cours. L'équivalent de ps aux pour Docker.
docker ps -a
docker build
Construire une image depuis un Dockerfile. Transforme ta recette en image utilisable.
docker build -t mon-app .
docker compose
Orchestrer plusieurs conteneurs. Lance toute ta stack en une seule commande.
docker compose up -d
docker exec
Exécuter une commande dans un conteneur en cours. Pour déboguer ou configurer.
docker exec -it app bash
docker logs
Voir les logs d'un conteneur. Indispensable pour déboguer ce qui se passe dedans.
docker logs -f mon-app
