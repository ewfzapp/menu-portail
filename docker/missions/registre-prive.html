Mission 20 — Intermédiaire

Héberger son propre registre d'images Docker

docker registryregistre privédocker push⏱ 15 min
Le scénario
Tu ne veux pas publier tes images maison sur Docker Hub public. Tu héberges ton propre registre privé sur ton serveur, accessible uniquement depuis ton réseau ou via authentification.

Ton Docker Hub personnel

01
Lancer le registre
L'image officielle registry:2 suffit pour un registre fonctionnel, stockage sur volume.
Lancer le registre
$ docker run -d -p 5000:5000 --name registry \ -v registre-donnees:/var/lib/registry registry:2
02
Pousser une image locale
Le tag doit inclure l'adresse du registre (hôte:port) pour que docker push sache où l'envoyer.
Push vers le registre local
$ docker tag mon-app:1.0 localhost:5000/mon-app:1.0
$ docker push localhost:5000/mon-app:1.0
03
Vérifier et retirer l'image
L'API du registre permet de lister le contenu, et docker pull confirme que ça fonctionne comme un registre classique.
Vérifier
$ curl http://localhost:5000/v2/_catalog
{"repositories":["mon-app"]}
$ docker pull localhost:5000/mon-app:1.0
💡 Depuis un autre serveur
docker refuse par défaut de parler en clair (non-HTTPS) à un registre distant — il faut soit du HTTPS (via un reverse proxy Traefik/nginx devant), soit déclarer le registre en 'insecure-registries' dans /etc/docker/daemon.json.
✅ Critères de réussite
  • Lancer un registre privé avec l'image registry:2
  • Retagger et pousser une image locale dessus
  • Lister le contenu via l'API _catalog
  • Comprendre la contrainte HTTPS pour un accès distant
