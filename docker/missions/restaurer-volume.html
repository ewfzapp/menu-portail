Mission 29 — Intermédiaire

Restaurer un volume depuis une sauvegarde

restoredocker volumetar⏱ 12 min
Le scénario
Un incident vient de survenir : le volume de production est corrompu. Tu as des sauvegardes régulières — c'est le moment de vérifier qu'elles fonctionnent vraiment en les restaurant.

La sauvegarde ne vaut que si elle se restaure

01
Créer un volume propre pour le test
Ne restaure jamais directement par-dessus la production sans avoir testé la procédure ailleurs d'abord.
Volume de test
$ docker volume create donnees-db-test
02
Extraire l'archive dans le volume
Le même principe de conteneur jetable, mais dans l'autre sens : extraction plutôt que compression.
Restaurer
$ docker run --rm \ -v donnees-db-test:/data \ -v $(pwd)/backups:/backup alpine \ tar xzf /backup/db-20260715.tar.gz -C /data
03
Vérifier avec un conteneur temporaire
Lance la base sur le volume restauré et vérifie que les données sont cohérentes avant de basculer en prod.
Vérifier
$ docker run -d --name test-restore -e POSTGRES_PASSWORD=demo \ -v donnees-db-test:/var/lib/postgresql/data postgres:15
$ docker exec -it test-restore psql -U postgres -c "\dt"
💡 Teste tes sauvegardes régulièrement
Une sauvegarde jamais restaurée en test n'est qu'une hypothèse. Planifie un test de restauration mensuel, même rapide, pour être sûr qu'elle fonctionne le jour où tu en as vraiment besoin.
✅ Critères de réussite
  • Restaurer une archive dans un volume neuf
  • Vérifier l'intégrité des données restaurées
  • Comprendre pourquoi tester en environnement isolé d'abord
  • Planifier un test de restauration récurrent
