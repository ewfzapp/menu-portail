Les commandes qu'on n'enseigne pas dans les tutoriels. Expliquées ici pour que tu comprennes ce qu'il ne faut JAMAIS faire — et pourquoi.

⚠ Niveau Dangereux — à utiliser avec précaution
rm -rf /
☠ NIVEAU APOCALYPSE
La commande la plus infâme de Linux. Elle supprime absolument tout ce qui est sur ton système. Le système d'exploitation, tes fichiers, tout. En quelques secondes. Sans confirmation. Sans retour arrière.
rm -r -f /
# rm = supprimer
# -r = récursivement (tout le contenu des dossiers)
# -f = forcer (aucune question posée)
# / = la RACINE de tout le système de fichiers
Ce qui se passe vraiment
Linux commence à supprimer à partir de / et descend dans TOUS les dossiers. /bin, /etc, /home, /var... tout y passe. En quelques secondes, le terminal ne répond plus. Le système est mort. Seul un format et réinstallation peut sauver la machine.
✓ L'alternative sûre
Pour supprimer un dossier spécifique : rm -rf /chemin/precis/du/dossier. Toujours vérifier deux fois le chemin avant d'appuyer sur Entrée.
:(){ :|:& };:
☠ FORK BOMB
La fork bomb. Une seule ligne de bash qui crée des processus à l'infini, exponentiellement, jusqu'à saturer complètement la mémoire et le CPU. Le système devient inutilisable en quelques secondes.
:() # Définit une fonction nommée ":"
{ :|:& }; # La fonction s'appelle elle-même deux fois
: # Lance la fonction → explosion exponentielle
La progression mortelle
1 processus → 2 → 4 → 8 → 16 → 32 → 64 → 128 → 256... En quelques itérations, des milliers de processus s'accumulent. Le système ne peut plus rien faire d'autre. Seul un redémarrage forcé (bouton power) peut sauver la situation.
✓ Protection
Dans /etc/security/limits.conf, définir * hard nproc 100 limite le nombre de processus par utilisateur et rend la fork bomb inoffensive.
⚠⚠ Niveau Extrême — effets irréversibles
dd if=/dev/zero of=/dev/sda
💀 DESTRUCTION DISQUE
Écrase intégralement le disque dur avec des zéros. Tout — système, données, partitions — est effacé de façon non récupérable. Utilisé légitimement pour effacer un disque avant de le revendre, mais dévastateur par erreur.
dd if=/dev/zero of=/dev/sda
# dd = disk duplicator
# if = input file : /dev/zero génère des zéros infinis
# of = output file : /dev/sda = ton premier disque dur
✓ Usage légitime
Pour créer une image ISO sur une clé USB : dd if=ubuntu.iso of=/dev/sdb bs=4M status=progress. Toujours vérifier of= avec lsblk avant d'exécuter.
chmod -R 777 /
💀 SÉCURITÉ ANÉANTIE
Donne à tout le monde tous les droits sur tous les fichiers du système. N'importe quel utilisateur peut lire, modifier ou supprimer n'importe quoi — y compris les mots de passe, les clés SSH, les configs critiques.
chmod -R 777 /
# -R = récursif (tout le système)
# 777 = rwxrwxrwx = tout le monde peut tout faire
# / = à partir de la racine
✓ L'alternative correcte
Pour rendre un dossier web accessible : chmod -R 755 /var/www/monsite. Toujours appliquer les permissions au chemin précis, jamais à /.
mv /home/* /dev/null
💀 PERTE DE DONNÉES
/dev/null est le "trou noir" de Linux — tout ce qu'on y envoie disparaît à jamais. Déplacer des fichiers vers /dev/null les efface irrémédiablement, sans confirmation.
mv /home/* /dev/null
# mv = déplacer
# /home/* = tous les dossiers utilisateurs
# /dev/null = le néant. Point de non-retour.
✓ Usage correct de /dev/null
/dev/null est utile pour supprimer la sortie d'une commande : commande 2>/dev/null supprime les messages d'erreur. Ne jamais l'utiliser comme destination de mv.
☠ Niveau Catastrophique — récits du monde réel
📖 L'incident GitLab — 2017
En janvier 2017, un ingénieur de GitLab effectuait une opération de maintenance sur le mauvais serveur. Il exécuta rm -rf sur la base de données de production au lieu de staging. 300 Go de données de 5000 clients supprimés. Les backups étaient défaillants. GitLab perdit 6 heures de données. L'ingénieur exécuta la commande publiquement, en livestream, devant des milliers de spectateurs. La transparence de GitLab dans la gestion de crise est devenue un modèle.
📖 La commande du vendredi soir
Un admin système voulait nettoyer un dossier temporaire. Fatigué après une longue semaine, il tapa rm -rf /tmp /mon-dossier avec une espace entre /tmp et /mon-dossier. Bash interpréta ça comme deux arguments séparés : supprimer /tmp ET /mon-dossier. Ce genre d'erreur de frappe a pris des serveurs de production entiers.
LES RÈGLES D'OR
01
Toujours tester une commande dangereuse avec echo devant — echo rm -rf ./dossier affiche ce qu'elle ferait sans l'exécuter.
02
Avant rm -rf, faire un ls sur le même chemin pour vérifier ce qui va être supprimé.
03
Ne jamais copier-coller une commande depuis internet sans la comprendre entièrement, mot par mot.
04
Toujours avoir une sauvegarde récente avant toute opération en production.
05
Si une commande te demande sudo et que tu n'es pas sûr de ce qu'elle fait, c'est le bon moment pour faire une pause.
06
La règle du principle of least privilege : toujours utiliser le compte avec le moins de droits nécessaires.
