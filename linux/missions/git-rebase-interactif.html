Mission 54 — Avancé

Nettoyer un historique de commits avant de le partager

Avancé ⏱ 22 min 🔧 git rebase, git log, git add
Le scénario
Ta branche contient 12 commits, dont plusieurs 'wip', 'fix typo', 'oups'. Avant d'ouvrir la pull request, l'historique doit raconter une histoire propre.
01
Lancer le rebase interactif
On cible les 12 derniers commits à nettoyer.
Démarrer le rebase
$ git rebase -i HEAD~12
pick a1b2c3d Ajout du formulaire de contact
pick e4f5g6h wip
pick i7j8k9l fix typo
pick m0n1o2p Validation côté client
02
Fusionner les petits commits avec squash
On remplace 'pick' par 'squash' (ou 's') pour fusionner un commit avec le précédent.
Fusionner avec squash
pick a1b2c3d Ajout du formulaire de contact
squash e4f5g6h wip
squash i7j8k9l fix typo
pick m0n1o2p Validation côté client
# 'wip' et 'fix typo' seront fusionnés dans le commit précédent
💡 Astuce
Après avoir sauvegardé, git ouvre un second écran pour réécrire le message de commit final unifié — c'est le moment de résumer clairement ce que fait réellement ce commit.
03
Résoudre un conflit pendant le rebase
Un rebase peut rencontrer des conflits, exactement comme un merge classique.
Gérer un conflit
CONFLICT (content): Merge conflict in src/formulaire.js
error: could not apply e4f5g6h...

# Éditer le fichier pour résoudre le conflit, puis :
$ git add src/formulaire.js
$ git rebase --continue
⚠ Attention
Ne fais jamais de rebase sur une branche déjà partagée et utilisée par d'autres personnes : cela réécrit l'historique et casse la synchronisation de tous ceux qui l'ont déjà récupérée.
✅ Critères de réussite
  • Lancer un rebase interactif sur les derniers commits
  • Fusionner plusieurs petits commits en un seul (squash)
  • Réécrire un message de commit peu clair
  • Résoudre un conflit pendant un rebase
