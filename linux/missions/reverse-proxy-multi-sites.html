Mission 39 — Avancé

Héberger 3 sites différents sur un seul serveur

Avancé ⏱ 25 min 🔧 nginx, ln, systemctl
Le scénario
Un seul VPS, mais trois clients avec chacun leur propre domaine. Il faut que nginx redirige chaque nom de domaine vers la bonne application, sur le même serveur.
01
Créer un fichier de config par domaine
Chaque site a son propre fichier dans sites-available, avec son server_name.
Config du premier site
root@vps:~# nano /etc/nginx/sites-available/client-a.fr
server {
listen 80;
server_name client-a.fr www.client-a.fr;
location / {
proxy_pass http://127.0.0.1:3001;
}
}
💡 Astuce
Chaque application backend tourne sur un port interne différent (3001, 3002, 3003...), invisible depuis l'extérieur : seul nginx écoute sur les ports 80/443 publics.
02
Répéter pour les autres domaines et activer
On active chaque config en créant un lien symbolique vers sites-enabled.
Activer les sites
root@vps:~# ln -s /etc/nginx/sites-available/client-a.fr /etc/nginx/sites-enabled/
root@vps:~# ln -s /etc/nginx/sites-available/client-b.fr /etc/nginx/sites-enabled/

# Toujours tester la syntaxe avant de recharger
root@vps:~# nginx -t
nginx: configuration file /etc/nginx/nginx.conf test is successful
03
Recharger nginx et vérifier chaque domaine
Le rechargement (reload) applique la config sans couper les connexions en cours, contrairement à un restart.
Recharger et tester
root@vps:~# systemctl reload nginx

$ curl -I http://client-a.fr
HTTP/1.1 200 OK
$ curl -I http://client-b.fr
HTTP/1.1 200 OK
⚠ Attention
server_name doit être exact et unique par bloc. Deux blocs avec le même nom (ou un oubli de www.) font que nginx sert le mauvais site à certains visiteurs.
✅ Critères de réussite
  • Créer un bloc server nginx par domaine
  • Rediriger chaque domaine vers la bonne application/port
  • Activer les configurations et tester la syntaxe
  • Vérifier que chaque domaine sert le bon contenu
